# 作品詳細画面の構成（フロントエンド）

## 概要

作品詳細で、作品の情報・メモ・人物・人物関係・出来事・気になるワードをどう切り替えて表示するかを決める。各タブの中身（表示項目・操作）の詳細設計は未着手。

人物関係の置き場所・操作は `docs/character-relation/plan.md` を参照。

## 決定事項

### ユーザー決定事項

- タブの表示（2026-11-01）
  - PC: アイコン + ラベル（横並び）
  - スマホ: アイコンの下に小さいラベル（縦並び）。タブは等幅で、横スクロールさせない
  - タブが増えて収まらなくなった時点で、アイコンのみ、または選択中のタブだけラベルを出す形に切り替える
  - スマホでアイコンのみにする案は、ユーザーから出たもの。目的はタブを収めることだけで、現在の5タブはラベル付きでも収まる見込みのため、収まらなくなるまでは見送る

### Claudeの提案（ユーザーは「お願い」とまとめを承認。以下の項目は個別の明示的な承認なし）

- P1: タブは URL を分けた子ルートにする（作品詳細を共通レイアウトにし、子ルートの内容を表示する）
  - 概要（作品の情報・メモ）: `/works/:workId`
  - 人物: `/works/:workId/characters`
  - 関係: `/works/:workId/relations`
  - 出来事: `/works/:workId/events`
  - ワード: `/works/:workId/words`
  - 共通レイアウトには、書籍へ戻るリンク・作品名・タブを置く
- P2: 人物詳細・出来事詳細はタブの外の別ページにする（`/characters/:id`・`/events/:id`。API の1件の URL と同じ形）。戻ると元のタブに戻る
- P3: タブは URL を切り替えるリンクとして作る（タブの UI 部品は未作成）。アイコンは導入済みの `react-icons` から選ぶ
- 選定理由: タブごとに一覧 API・操作が独立しており、URL を分けるとページ・データ取得・API の単位がそろう。詳細画面からブラウザの「戻る」で元のタブに戻れる
- 見送った案
  - 同じ URL でクエリパラメータ（`?tab=`）により切り替える: 1つのページに5種類の表示・データ取得が集まり、タブを足すたびに同じファイルを修正することになる
  - 1ページに全セクションを縦に並べる: 開くたびに全一覧を取得する。スマホで長くなり、関係のグラフ表示が収まらない

### タブが収まるかの見積もり（Claudeの見積もり。実機・ブラウザでは未確認）

- ラベル 12px・3文字（約 36px）+ 左右の余白 4px ずつ
- 360px 幅（使える幅 328px）: 7タブまで収まる
- 320px 幅（使える幅 288px）: 6タブまで収まる。7タブが境目

## 画面イメージ

レイアウト・タブの表示を示すためのもの。各タブの中身（カードの項目・操作ボタン等）は既存の API の項目から仮に置いたもので、各タブの詳細設計で決める。アイコンは位置を示す仮の絵文字（実際は `react-icons` から選ぶ）。

## 未決定事項

- 各タブの表示項目・操作（人物カードの項目、出来事の並び替えの操作、ワードの表示項目など）
- 各タブのアイコン
- 論理削除された作品の詳細画面でのタブの扱い（`docs/delete-restore/plan.md` P9: 削除済みの詳細画面では編集できず、[復元]・[完全に削除] だけを置く）

## 破綻ケース

- タブが 7〜8 個以上に増えた場合: アイコンのみにしても見分けにくくなるため、タブをまとめる（例: 関係を人物タブの中に入れる）か、サイドメニュー等への変更が必要になる
- タブをまたいで同時に表示する要件（例: 人物と出来事を並べて見る）が出た場合: タブで分ける構成と衝突する
- メモを複数件の独立したデータにする場合: 概要の1項目では足りず、メモのタブの追加が必要になる
- 文字サイズを大きくする設定の利用者: 見積もりより早く収まらなくなる可能性がある
